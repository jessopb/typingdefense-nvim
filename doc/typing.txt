1. INTRODUCTION                                          *typing-introduction*

typing.nvim is a small typing-practice game that runs inside a normal
Neovim window. Starting a test replaces the current window's buffer with
the practice text; your original buffer is restored automatically when the
test finishes or is aborted.

Three modes are supported:

  - Words:   random common English words, Monkeytype-style.
  - Lesson:  progressive home-row key drills using generated pseudo-words,
             for building raw muscle memory one key at a time.
  - Defense: words fall from the top of the screen towards a city on the
             horizon; type each one before it lands. See |typing-defense|.

In Words and Lesson mode, every keystroke is compared against the expected
character: correct characters are highlighted one way, mistakes another,
and <BS> steps back to fix a mistake. The test ends automatically once the
last character has been typed, showing WPM, accuracy, elapsed time, and a
mistake count.

Press <Esc> or <C-c> at any point during a test to abort it without
scoring.

2. COMMANDS                                                  *typing-commands*

                                                                *:TypingWords*
:TypingWords [{count}]
    Start a random-word typing test. {count} defaults to the
    |typing-config| `word_count` option.

                                                               *:TypingLesson*
:TypingLesson [{stage}]
    Start a home-row drill lesson. {stage} is a number from 1 up to the
    number of stages defined in |typing-lessons| (defaults to the
    |typing-config| `lesson.stage` option). Each stage cumulatively adds
    two new keys to drill, spreading out from the home row.

                                                               *:TypingDefense*
:TypingDefense
    Start typing-defense. See |typing-defense|.

                                                                 *:TypingStop*
:TypingStop
    Abort the current test or defense game (if any) and restore the
    previous buffer.

                                                       *:TypingKeyboardPreview*
:TypingKeyboardPreview [{at}] [{from}]
    Open a floating preview of the keyboard hint diagram (see
    |typing-defense|). With no arguments, shows the default board. With
    {at}, relocates the finger-outline to that key and highlights it (e.g.
    `:TypingKeyboardPreview U`); with {from} as well, also reverts that key
    to a plain square, simulating a finger leaving home to reach {at} (e.g.
    `:TypingKeyboardPreview U J`). q/<CR>/<Esc> closes the preview.

3. CONFIGURATION                                                *typing-config*

Call `setup()` to override any of the defaults below: >lua

    require("typing").setup({
      word_count = 25,
      words = nil, -- override the built-in word list

      highlights = {
        pending   = "Comment",
        correct   = "String",
        incorrect = "ErrorMsg",
        cursor    = "CursorLine",
        key_hint  = "Todo", -- relocated finger-outline in the keyboard diagram
      },

      lesson = {
        stage = 1,
        word_count = 30,
        word_length = { 2, 5 },
      },

      defense = {
        lives = 3,
        fall_interval_ms = 500, -- how often the falling word drops one row
      },
    })
<
`setup()` is optional — all commands work with built-in defaults even if
it is never called.

Suggested keymaps (not set by default): >lua

    vim.keymap.set("n", "<leader>tw", "<cmd>TypingWords<cr>")
    vim.keymap.set("n", "<leader>tl", "<cmd>TypingLesson<cr>")
<

4. LESSONS                                                    *typing-lessons*

Lesson stages introduce keys two at a time (mirrored across both hands),
starting at the home row and spreading outward:

    1.  f j        6.  r u       11. c ,
    2.  d k        7.  e i       12. x .
    3.  s l        8.  w o       13. z /
    4.  a ;        9.  q p       14. t y
    5.  g h        10. v m       15. b n

Each stage is cumulative: stage 3 drills keys from stages 1-3 together.
Generated words guarantee at least one occurrence of the current stage's
newly-introduced keys, so each stage actually exercises the new key
instead of diluting it among review material.

==============================================================================
5. DEFENSE                                                    *typing-defense*

:TypingDefense splits the buffer into two regions:

  - A "sky" at the top where one word at a time falls, one row per tick
    (`defense.fall_interval_ms`), towards a city/horizon line.
  - A keyboard hint diagram at the bottom (the same one |:TypingKeyboardPreview|
    shows): the key for the next character you need to type is drawn with
    the finger-outline and highlighted via `TypingKeyHint`.

Type the falling word's characters in order. A correct keystroke advances
it (turning that part of the word green); an incorrect keystroke does NOT
advance -- it just counts as a miss, so a word can only be cleared by
typing it exactly. Clearing a word increases your score and spawns a new
one; if a word reaches the city you lose one of your `defense.lives`. When
lives run out, a summary screen shows words cleared and total misses.

<Esc>/<C-c> aborts the game immediately (no summary), same as the other
modes.

Note: the keyboard diagram only models the keys drawn in |typing-lessons|'
layout (letters, `{ } < > ? : "`), not every symbol -- a word containing an
apostrophe (there's exactly one in the built-in word list: "don't") is
still fully typable, it just won't get a keyboard hint for that character.

The keyboard diagram currently only highlights the literal next key --
relocating the outline from a specific home-row finger (as
|:TypingKeyboardPreview|'s {from} argument demonstrates manually) requires
a finger-to-key dictionary that doesn't exist yet.

==============================================================================
6. HIGHLIGHTS                                              *typing-highlights*

The plugin defines (and links, so they respect your colorscheme/overrides)
these highlight groups:

    TypingPending      Untyped text.
    TypingCorrect       Correctly typed characters.
    TypingIncorrect     Incorrectly typed characters.
    TypingCursor        The next character to be typed.
    TypingKeyHint        The relocated/highlighted key in the keyboard
                          hint diagram (|typing-defense|).

Link targets are controlled via the `highlights` table in |typing-config|,
or override the groups directly after `setup()`: >lua

    vim.api.nvim_set_hl(0, "TypingIncorrect", { fg = "#ff0000", bold = true })
<
