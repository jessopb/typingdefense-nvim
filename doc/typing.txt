1. INTRODUCTION                                          *typing-introduction*

typing.nvim is a small typing-practice game that runs inside a normal
Neovim window. Starting a test replaces the current window's buffer with
the practice text; your original buffer is restored automatically when the
test finishes or is aborted.

Four modes are supported:

  - Words:   random common English words, Monkeytype-style.
  - Lesson:  progressive home-row key drills using generated pseudo-words,
             for building raw muscle memory one key at a time.
  - Defense: words fall from the top of the screen towards a city on the
             horizon; type each one before it lands. :TypingDefense opens a
             mode-select splash: Word Speed (random common words), Learning
             (a curated key-introduction curriculum), or Code Speed (not
             implemented yet). See |typing-defense|.
  - Boss:    a stationary ship hovers at the top; type the word in each of
             its zones (3 to 9, depending on the ship) to destroy it while
             dodging bomb waves. See |typing-boss|.

In Words and Lesson mode, every keystroke is compared against the expected
character: correct characters are highlighted one way, mistakes another,
and <BS> steps back to fix a mistake. The test ends automatically once the
last character has been typed, showing WPM, accuracy, elapsed time, and a
mistake count.

Press <Esc> or <C-c> at any point during a test to abort it without
scoring.

2. COMMANDS                                                  *typing-commands*

                                                                *:TypingWords*
:TypingWords [{count}]
    Start a random-word typing test. {count} defaults to the
    |typing-config| `word_count` option.

                                                               *:TypingLesson*
:TypingLesson [{stage}]
    Start a home-row drill lesson. {stage} is a number from 1 up to the
    number of stages defined in |typing-lessons| (defaults to the
    |typing-config| `lesson.stage` option). Each stage cumulatively adds
    two new keys to drill, spreading out from the home row.

                                                               *:TypingDefense*
:TypingDefense
    Open typing-defense's mode-select splash: press `1` for Learning, `2`
    for Word Speed, `3` for Code Speed (not implemented -- shows a notice
    and stays on the splash), or <Esc>/<C-c> to cancel. See |typing-defense|.

                                                       *:TypingDefenseLearning*
:TypingDefenseLearning [{stage}]
    Skip the splash and go straight to learning mode: falling words are
    drawn from a curated key-introduction curriculum stage instead of
    random common words. {stage} is a number from 1 up to the number of
    stages in `typing.curriculum` (defaults to the |typing-config|
    `defense_learning.stage` option; out-of-range values are clamped). See
    |typing-defense|.

                                                                  *:TypingBoss*
:TypingBoss [{name}]
    Start the boss level. See |typing-boss|. {name} selects a ship from the
    `typing.ships` registry -- `"cruiser"` (the default) plus the ten-ship
    `typing.ships.CAMPAIGN` roster (`"skiff"`, `"interceptor"`,
    `"corvette"`, `"frigate"`, `"gunship"`, `"destroyer"`,
    `"battlecruiser"`, `"carrier"`, `"juggernaut"`, `"leviathan"`) -- and
    defaults to the |typing-config| `boss.ship` option. Unknown names fall
    back to `"cruiser"`.

                                                                 *:TypingStop*
:TypingStop
    Abort the current test, defense game, or boss fight (if any) and
    restore the previous buffer.

                                                       *:TypingKeyboardPreview*
:TypingKeyboardPreview [{at}] [{from}]
    Open a floating preview of the keyboard hint diagram (see
    |typing-defense|). With no arguments, shows the default board. With
    {at}, relocates the finger-outline to that key and highlights it (e.g.
    `:TypingKeyboardPreview U`); with {from} as well, also reverts that key
    to a plain square, simulating a finger leaving home to reach {at} (e.g.
    `:TypingKeyboardPreview U J`). q/<CR>/<Esc> closes the preview.

3. CONFIGURATION                                                *typing-config*

Call `setup()` to override any of the defaults below: >lua

    require("typing").setup({
      word_count = 25,
      words = nil, -- override the built-in word list

      highlights = {
        pending   = "Comment",
        correct   = "String",
        incorrect = "ErrorMsg",
        cursor    = "CursorLine",
        key_hint  = "#ffff00", -- relocated finger-outline in the keyboard
                                -- diagram; a literal hex color (bright
                                -- yellow), not a link target like the rest
                                -- of this table, so it stays vivid
                                -- regardless of colorscheme
        laser     = "Special",       -- the turret beam (defense and boss)
        explosion = "DiagnosticWarn",-- word/zone-destroyed flash and embers
        boss_active   = "Todo",      -- boss mode's currently-typeable zone
        boss_inactive = "Comment",   -- boss mode zones not active yet, or destroyed
        energy    = "String",        -- filled portion of the energy bar (defense and boss)
      },

      lesson = {
        stage = 1,
        word_count = 30,
        word_length = { 2, 5 },
      },

      defense_learning = {
        stage = 1, -- default stage for :TypingDefenseLearning
        words_per_stage = 40, -- words cleared before auto-advancing to the
                               -- next stage; stays on the last stage once reached
        boss_stages = { 1, 2, 3, 4, 6, 8, 10, 12, 14, 16 }, -- curriculum
                               -- stages that hand off to a boss fight (see
                               -- |typing-boss|) instead of auto-advancing
                               -- straight through; boss_stages[i] pairs with
                               -- typing.ships.CAMPAIGN[i], so bosses show up
                               -- small first and get bigger/badder as you go.
                               -- {} disables boss interludes entirely.
      },

      defense = {
        lives = 3,
        fall_interval_ms = 1000, -- how often the falling word drops one row,
                                 -- tuned for speed_reference_height
        speed_reference_height = 20, -- sky_height fall_interval_ms is tuned
                                      -- for; taller/shorter play areas scale
                                      -- speed to compensate
        laser_ms = 90,          -- how long the word-destroying kill shot stays on screen
        shot_ms = 70,           -- how long a per-keystroke shot stays on screen (never
                                 -- freezes play, unlike laser_ms)
        explosion_frames = 5,   -- animation steps in the ember spray
        explosion_frame_ms = 45,-- delay between ember animation steps
        energy_max = 20,        -- width (in bars) of the energy meter
        target = {
          -- the targeting-square corners fade from `gray` to `red` as the
          -- current word goes from untyped to fully typed
          gray = "#585858",
          red = "#ff3333",
        },
      },

      boss = {
        lives = 3,
        ship = "cruiser",       -- which typing.ships registry entry to use
        fall_interval_ms = 500, -- bomb fall speed (same speed_reference_height
        speed_reference_height = 20, -- scaling idea as defense, above)
        laser_ms = 90,
        shot_ms = 70,           -- see defense.shot_ms
        explosion_frames = 5,
        explosion_frame_ms = 45,
        energy_max = 20,        -- see defense.energy_max
        bomb_interval_ms = 9000, -- how often the ship launches a 2-bomb wave
      },
    })
<
`setup()` is optional — all commands work with built-in defaults even if
it is never called.

Suggested keymaps (not set by default): >lua

    vim.keymap.set("n", "<leader>tw", "<cmd>TypingWords<cr>")
    vim.keymap.set("n", "<leader>tl", "<cmd>TypingLesson<cr>")
<
==============================================================================
4. LESSONS                                                    *typing-lessons*

Lesson stages introduce keys two at a time (mirrored across both hands),
starting at the home row and spreading outward:

    1.  f j        6.  r u       11. c ,
    2.  d k        7.  e i       12. x .
    3.  s l        8.  w o       13. z /
    4.  a ;        9.  q p       14. t y
    5.  g h        10. v m       15. b n

Each stage is cumulative: stage 3 drills keys from stages 1-3 together.
Generated words guarantee at least one occurrence of the current stage's
newly-introduced keys, so each stage actually exercises the new key
instead of diluting it among review material.

5. DEFENSE                                                    *typing-defense*

:TypingDefense opens a mode-select splash rather than starting a game
directly -- press `1`/`2`/`3` to pick a mode, or <Esc>/<C-c> to cancel back
to your original buffer with nothing started:

  - `1` Learning: words come from one stage of the `typing.curriculum`
    module (transcribed from a curated 17-stage key-introduction course --
    home row first, then progressively further reaches, ending in
    punctuation), same idea as |typing-lessons| but with hand-picked
    drills/words per stage instead of generated pseudo-words. The status
    line is prefixed with the stage number, title, and focus so you know
    what you're practicing. Every `defense_learning.words_per_stage` words
    cleared (default 40), it auto-advances to the next stage -- no need to
    restart the game to move on -- staying on the last stage once reached.
    Equivalent to :TypingDefenseLearning with no {stage} argument (which
    also lets you jump straight to a specific
    stage, skipping the splash).

    Learning mode also tracks points, shown in the status line and on the
    end screen: each stage is worth a base value of `stage number * 100`,
    scaled by your keystroke accuracy on that stage. E.g. stage 1 finished
    at 80% accuracy banks `100 * 0.80 = 80` points; stage 2 at 75% banks
    `200 * 0.75 = 150`. Points bank (added to a running total) when a stage
    is cleared via auto-advance, and the current stage's points bank too
    once the game ends, so nothing typed is lost if the city falls
    mid-stage. Word Speed and Code Speed have no stage curve, so they don't
    track points.

    Stages listed in `defense_learning.boss_stages` (default: 1-4, then
    every 2nd stage through 16) interrupt the auto-advance with a boss
    fight (|typing-boss|) instead of continuing straight on: the falling-word
    session stops, a ship from `typing.ships.CAMPAIGN` appears restricted to
    the stage you just cleared's keys, and once you win or lose it (either
    way -- the fight doesn't gate progress) dismissing its summary screen
    resumes curriculum practice on the next stage, carrying your points
    total across the interlude. The roster is ordered smallest/weakest
    first, so the boss fights escalate right alongside the curriculum.
  - `2` Word Speed: random words from `words`/`word_count`'s pool, same as
    Words mode -- a pure speed/accuracy drill, no curriculum gating.
  - `3` Code Speed: not implemented yet -- shows a notice and leaves the
    splash open.

All three modes (once started) share one engine and buffer layout --
:TypingDefenseLearning and `require("typing").start_defense_speed()` reach
the same underlying game as picking `1`/`2` from the splash, just without
going through it first.

The buffer itself splits into two regions either way:

  - A "sky" at the top where one word at a time falls, one row per tick
    (`defense.fall_interval_ms`), towards a city/horizon line.
  - A keyboard hint diagram at the bottom (the same one |:TypingKeyboardPreview|
    shows): the key for the next character you need to type is drawn with
    the finger-outline and highlighted via `TypingKeyHint`.

Type the falling word's characters in order. A correct keystroke advances
it (turning that part of the word green); an incorrect keystroke does NOT
advance -- it just counts as a miss, so a word can only be cleared by
typing it exactly. A four-corner targeting square brackets the word and
fades from gray to red as you type it.

The turret fires on every keystroke, not just the word-clearing one: a hit
aims at the word (a quick `defense.shot_ms` flash if the word isn't done
yet), a miss goes wide and fires at a random cell instead. Neither flash
interrupts play -- keystrokes keep landing at full speed either way.
Clearing a word is the one keystroke that's different: it fires a longer
`defense.laser_ms` beam that bursts into a short ember-spray explosion,
increases your score, and spawns a new word -- input freezes for that beam
and explosion, same as before. If a word reaches the city you lose one of
your `defense.lives`. When lives run out, a summary screen shows words
cleared and total misses.

An energy meter (`Energy: [||||       ]`, `defense.energy_max` bars wide,
`TypingEnergy`-colored) tracks accuracy near the bottom of the play area,
above the keyboard hint: starts full and every keystroke costs 1 bar, but a
hit refunds 1.1 -- netting +0.1 per correct keystroke, while a miss costs a
full bar outright. Floor-rounded for display, clamped to [0, energy_max].
Draining it to 0 ends the game too ("The turret runs out of power!"),
independently of `defense.lives` -- sustained accuracy keeps it topped up
near full, but a run of misses (even with plenty of lives left) empties
the tank and ends the run just as surely as a word reaching the city.

The fall speed (`defense.fall_interval_ms`) is tuned for a sky
`defense.speed_reference_height` rows tall; taller or shorter windows scale
the actual per-row delay to compensate, so a word takes roughly the same
real time to cross the screen regardless of terminal height.

<Esc>/<C-c> aborts the game immediately (no summary), same as the other
modes.

Note: the keyboard diagram only models the keys drawn in |typing-lessons|'
layout (letters, `{ } < > ? : "`), not every symbol -- a word containing an
apostrophe (there's exactly one in the built-in word list: "don't") is
still fully typable, it just won't get a keyboard hint for that character.
The same applies to :TypingDefenseLearning's punctuation stage (comma,
period, slash, double/single quote, `!`): fully typable, no keyboard hint.

The keyboard diagram currently only highlights the literal next key --
relocating the outline from a specific home-row finger (as
|:TypingKeyboardPreview|'s {from} argument demonstrates manually) requires
a finger-to-key dictionary that doesn't exist yet.

6. BOSS                                                            *typing-boss*

:TypingBoss hovers a stationary ASCII ship at the top of the window (a "row
of pods" joined by hull segments, each pod a zone showing a word). {name}
selects a ship from `typing.ships.ships` (default: `boss.ship`, itself
`"cruiser"`) -- see the roster below.

Only one zone is "active" (typeable) at a time -- shown in amber
(`TypingBossActive`); the rest are dimmed (`TypingBossInactive`). The game
picks the activation order itself: every non-bridge zone in a random
order, then the bridge always last, so the bridge is implicitly shielded
until every other zone is destroyed. Destroy every zone to win.

The turret fires on every keystroke, not just the destroying one: a hit
aims at whatever it's typing towards -- the active zone, or a bomb once a
wave is up -- with a quick `boss.shot_ms` flash if that isn't destroyed
yet; a miss goes wide and fires at a random cell in the bomb-fall gap
instead. Neither flash interrupts play. The keystroke that actually
destroys a zone or bomb fires a longer `boss.laser_ms` beam that explodes
it into wreckage (or ember-sprays a downed bomb) and activates the next
zone -- input freezes for that beam/explosion, same as before.

Periodically (`boss.bomb_interval_ms`) the ship launches two bombs at once,
each with a different first letter so there's never any ambiguity about
which one your keystrokes are aimed at. A bomb wave interrupts targeting:
your keystrokes go to the bombs until both are destroyed or fall past the
bottom, and the active zone's typed progress is reset to 0 (it stays the
active zone -- you just have to retype it once the wave clears).

Every wrong keystroke -- against the active zone or a bomb -- costs one of
your `boss.lives`, same as a bomb that reaches the bottom un-typed. Run out
of lives and the ship's counterattack ends the fight; destroy every zone
first and you win. Either way a summary screen shows your score and total
misses.

An energy meter tracks accuracy near the bottom of the play area, same
`energy_max`/scoring/coloring as |typing-defense|'s (`boss.energy_max`,
`boss.shot_ms`) -- see there for the exact rule. Same stakes too: draining
it to 0 ends the fight as a loss, independently of `boss.lives`.

Ship layouts are data, not hand-drawn art: `require("typing.ships")`
exposes a small pod/row builder (`M.build(ship_def)`) plus a `M.ships`
registry, so new boss ships can be added by describing pods (id, kind,
label, width, and optionally cap/row_offset) rather than drawing new ASCII.
Pods read left to right like a real hull -- a pointed nose pod leads,
engines trail at the back (amidships for `carrier`) -- and `row_offset`
lets a pod sit above or below its neighbors, so a ship doesn't have to be a
single flat row (`skiff` uses this for a small raised-bridge "hump"
silhouette). The whole ship is centered in the play area, evenly padded
left and right. `M.CAMPAIGN` orders ten of them smallest/weakest to
largest/baddest -- the 3-pod `skiff` through `interceptor` (4),
`corvette`/`frigate` (5), `gunship`/`destroyer` (6), `battlecruiser` (7),
`carrier`/`juggernaut` (8), up to the 9-pod `leviathan` -- the same order
|typing-defense|'s Learning mode walks through for its
`defense_learning.boss_stages` interludes.

<Esc>/<C-c> aborts the fight immediately (no summary), same as the other
modes.

7. HIGHLIGHTS                                              *typing-highlights*

The plugin defines (and links, so they respect your colorscheme/overrides)
these highlight groups:

    TypingPending      Untyped text.
    TypingCorrect       Correctly typed characters.
    TypingIncorrect     Incorrectly typed characters.
    TypingCursor        The next character to be typed.
    TypingKeyHint        The relocated/highlighted key in the keyboard
                          hint diagram (|typing-defense|).
    TypingLaser          The turret beam and its base (|typing-defense|,
                          |typing-boss|).
    TypingExplosion      The word/zone-destroyed flash and ember spray
                          (|typing-defense|, |typing-boss|).
    TypingBossActive      The boss level's currently-typeable ship zone
                          (|typing-boss|).
    TypingBossInactive    Boss level zones that aren't active yet, or have
                          been destroyed (|typing-boss|). Also reused by the
                          :TypingDefense splash for its disabled Code Speed
                          entry; the splash's enabled entries reuse
                          TypingKeyHint rather than defining new groups.
    TypingEnergy          The filled portion of the energy bar
                          (|typing-defense|, |typing-boss|).

Link targets are controlled via the `highlights` table in |typing-config|,
or override the groups directly after `setup()`: >lua

    vim.api.nvim_set_hl(0, "TypingIncorrect", { fg = "#ff0000", bold = true })
